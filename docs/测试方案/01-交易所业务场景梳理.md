# 交易所业务场景梳理

把交易所（现货、合约、资产）拆成几块，搞清楚每块在干什么、数据从哪来到哪去，后面写用例和划范围就好办。**读完本文你能**：说清业务分几块、用户主流程、现货与合约差异、撮合/杠杆/清算/风控在干啥、关键术语不懵；面试或汇报时被问到「你了解交易所业务吗」能答到点子上。

---

## 一、业务分几块

| 块 | 干啥的 | 主要有什么 | 测的时候盯啥 |
|----|--------|------------|--------------|
| 用户与账户 | 注册、KYC、登录、谁能动啥、子账户 | 用户、账户、角色、权限 | 身份和权限别串、多端数要对上 |
| 资产与钱包 | 充钱、提钱、内部划转、查余额、看流水 | 币种、钱包、流水、手续费 | 钱数一致、同一笔别重复入账、并发别乱、限额要生效 |
| 交易与订单 | 下单、撤单、撮合、成交、订单变来变去 | 订单、成交、订单簿、撮合引擎 | 订单状态别乱、价格数量精度、撮合规则按说好的来 |
| 行情与盘口 | 深度、K 线、最新价、涨跌 | 行情、深度、ticker | 推得及时、数和库/缓存对上 |
| 风控与限额 | 单笔/每日限额、黑名单、异常拦一下 | 限额、规则、告警 | 限额真拦住、熔断要生效 |
| 清算与对账 | 日终算一遍、对账、出报表 | 清算任务、对账结果 | 数一致、钱平、能审计 |

## 二、主流程：用户从注册到提现

一条线串起来：

```
注册/登录 → KYC(看业务要不要) → 充值 → 下单 → 撮合成交 → 看持仓/成交 → 提现
```

- **注册/登录**：手机/邮箱/第三方、验证码，有的会看设备/IP 防风控。
- **充值**：选链选币、拿充值地址或二维码、链上到账后按确认数入账、改余额、记流水。
- **下单**：选交易对、买还是卖、限价还是市价、填价格数量，丢给下单接口，进订单簿等着撮。
- **成交**：撮合引擎算出成交、改订单状态、改两边余额/持仓、推成交回报。
- **提现**：选币选链、填地址和数量、先过风控和限额、扣余额、发链上 tx、等回调改状态和流水。

### 订单和撮合这块

- 订单分限价、市价、有的还有止损止盈。
- 状态一堆：待报、已报、部分成交、全成、部分撤、已撤、废单等，要能画清楚怎么变。
- 撮合一般是价格优先、时间优先；市价单按盘口吃。
- 要紧的是：同一笔订单，在 DB、缓存、推给前端的「状态 + 成交明细 + 账户余额/持仓」得对得上。

### 钱怎么动

- 余额分：可用、冻结（挂单占的）、待入账（充了还没确认够）。
- 流水：每笔变动记一条，类型（充值/提现/成交/划转/手续费等）、方向、金额、前后余额、关联单号。
- 划转（比如现货↔合约）：划完两边总资产除了手续费不能变，可用和冻结要算对。

### 现货 vs 合约（差异要搞清）

| 维度 | 现货 | 合约 |
|------|------|------|
| 标的 | 直接买/卖币 | 合约（多空、杠杆），有到期或永续 |
| 资金 | 余额、冻结（挂单） | 保证金、占用、未实现盈亏、强平线 |
| 结算 | 成交即交割 | 可持仓、资金费、强平、穿仓/风险金 |
| 测试重点 | 订单与成交一致、余额与流水 | 再加：保证金率、强平顺序、资金费方向、标记价/指数价 |

面试常问「现货和合约测试有什么不同」：合约多出杠杆、强平、清算、资金费、标记价，测试要额外覆盖这些规则和一致性。

## 三、主要有哪些「东西」（写用例会用到）

- **用户** 下面有 **账户**（还能分子账户）；账户下有 **余额**（按币种）、**订单**、**成交**、**流水**；合约账户还有 **持仓**。
- **交易对**：基础币 + 计价币、精度、最小下单量、上架还是下架。
- **订单**：谁、哪个交易对、买还是卖、类型、价格数量、状态、成交了多少、手续费等。
- **成交**：挂在哪个订单上、成交价、成交量、买卖方、手续费、时间。
- **持仓**（合约）：用户、交易对、方向（多/空）、数量、开仓均价、占用保证金、杠杆倍数等；**开仓**=新建仓位，**加仓**=同方向增加持仓，**减仓**=同方向减少持仓，**平仓**=仓位归零。
- **充值地址/钱包**：用户、币种、链、地址；充值按链上 tx 来入账。

## 四、撮合、杠杆、清算、风控（业务上咋回事、测的时候盯啥）

这几块是交易所里最容易「钱错、数乱」的地方，业务场景梳理时要搞清楚系统在干啥、边界在哪、容易出啥问题。

### 4.1 撮合

**在干啥**：把买单和卖单按规则对上，生成成交记录，改订单状态、改两边余额/持仓、推回报。核心是订单簿 + 撮合引擎。

- **价格优先、时间优先**：同价谁先挂谁先成；不同价买高卖低先碰在一起。测的时候要验证同一时刻多笔单进来，成交顺序是否符合规则，不能「后到的单先成交」。
- **部分成交**：大单拆成多笔成交，订单状态是「部分成交」、剩余挂单还在簿子里；撤单只撤未成交部分。要盯：部分成交后余额/冻结对不对、撤单后冻结是否只释放未成交部分、成交明细汇总是否等于订单已成交量。
- **市价单**：按盘口吃，可能全成也可能只成一部分。要盯：吃到的价格和当时盘口是否一致、数量不够时是否部分成交并正确处理剩余。
- **订单簿一致性**：撮合引擎改了一笔单，DB 里订单状态、成交表、账户冻结/余额、推给前端的回报要一致。压测或并发时最容易「引擎说成了、DB 没跟上」或「冻结多扣少还」。
- **边界**：数量为 0、超过精度、超限、交易对下架、撤已全成的单（应幂等），都要有明确错误码、不产生脏数据。撮合和账户/持仓是两套系统时，靠消息或异步对账，延迟或重试会导致「成交回报先到、余额还没变」或重复扣款，测试要造延迟场景做一致性校验。

### 4.2 杠杆（含开仓、加仓、减仓、平仓、强平）

**在干啥**：用户开杠杆仓位，用保证金占用放大敞口；系统按「保证金率」「强平线」算能不能开仓/加仓、要不要强平。

- **开仓 / 加仓 / 减仓 / 平仓**：**开仓**=首次建多或建空；**加仓**=同方向再开，持仓量增加、占用和开仓均价重算；**减仓**=同方向平掉一部分，持仓量减少、释放保证金、实现部分盈亏；**平仓**=全部平掉，仓位归零。要盯：加仓后占用和均价对不对、减仓后释放的保证金和盈亏进余额是否正确、部分减仓后剩余持仓的占用与强平线重算。
- **保证金与占用**：开多/开空时占用多少保证金（全仓/逐仓算法不一样）。加减仓、改杠杆倍数时，占用和可用要重算；总权益 = 余额 + 未实现盈亏，可用 = 总权益 - 占用 - 其他冻结。要盯：开仓后占用对不对、加减仓/改杠杆后占用和可用是否重算正确。
- **强平线**：保证金率掉到阈值就触发强平。要盯：用**标记价/指数价**（不用最新成交价）算保证金率，避免**插针**导致误爆；到线就强平、没到就不强平；强平后仓位为 0、盈亏结算进余额、流水和持仓变更正确。同一用户多仓位时先平哪个（有的按风险从高到低）、多用户同时强平谁先被平，规则要能说清并验证。
- **杠杆倍数上下限**：不同交易对或账户可能有最大杠杆限制；改杠杆时若仓位已经很大可能不许再调高。要盯：边界倍数、调高/调低后占用和强平线重算是否正确。容易错的地方：标记价/指数价取错（取成最新成交价被插针）、强平方向反了、强平后余额没加减、强平单进撮合没成交导致「强平失败」但仓位还在。

### 4.3 清算

**在干啥**：把「该平的仓」「该结的钱」算清楚并执行，包括强平、资金费结算、穿仓分摊、风险准备金等。

- **什么时候触发**：强平（保证金率到线）、资金费结算（按周期）、有的还有 ADL（自动减仓）或手工清算。要盯：触发时任务真的跑、该平的仓被平、该扣该加的钱都进流水和余额。
- **资金费**：多空双方按标记价和资金费率互付。要盯：费率取对、正负方向对（谁付谁收）、结算后余额和流水一致、没重复扣或漏扣。
- **穿仓与风险准备金**：强平后亏损超过保证金（穿仓）时，用风险准备金或盈利方分摊填坑。要盯：穿仓时从风险准备金扣、准备金不够时的分摊规则、流水和报表里能体现「穿仓」「风险金」类型。
- **标记价 vs 指数价**：强平和资金费通常用标记价或指数价，**不用最新成交价**，就是为了防**插针**（盘口瞬间剧烈波动、一根针打穿很多止损/强平，再用最新价算会误爆）。要盯：取价来源对、异常行情下标记价/指数价按规则（如限幅、延时）计算。容易错：日终或定时任务没跑、跑了一半失败导致部分用户结了部分没结、资金费方向反了、穿仓没从风险金扣而从错误账户扣。

### 4.4 风控

**在干啥**：在下单、撤单、提现、开仓、强平等环节拦异常，防止刷单、超限、盗号、系统被拖垮。

- **限额**：单笔最大下单量、单日最大提现、单日笔数、单用户最大持仓等。要盯：到限就拒、错误码明确、不会「超了还通过」；限额定在配置里，改配置后新限要生效。
- **熔断**：达到阈值时**直接停或缩范围**（如行情剧烈时暂停交易、只允许撤单禁止开新仓）。要盯：触发条件（涨跌幅、波动率、错误率等）满足时接口真的拒单或只接受撤单、恢复后能正常下单；压测时验证触发后行为一致。
- **降级**：系统压力大或依赖异常时**关掉非核心能力、保核心**（如关行情推送、只保留下单撤单查余额；或提现排队、延迟处理）。要盯：降级开关生效后，该关的接口/功能真的不可用或限流、核心路径仍可用；恢复后功能回来。
- **异常检测**：频繁撤单、自成交、对倒、小单试盘等，有的会限频或封禁。要盯：规则触发后用户被限制、有日志或后台记录、不误伤正常用户。
- **黑名单**：地址、用户、IP、设备等禁止提现或交易。要盯：命中就拒、不扣钱不成交、提示明确。敏感操作（提现、改杠杆、API 密钥等）有的要二次验证或白名单，要盯：没验证就拒、验证通过才放行。风控和交易/账户是不同服务时，配置没同步会导致「前端拦了、后端又接受」或反过来；压测时要验证限流、熔断在高压下仍然生效。

## 五、关键术语速查（面试/排查时别懵）

| 术语 | 一句话 |
|------|--------|
| 订单簿 | 当前所有未成交的买卖挂单集合，按价格时间排序 |
| 撮合引擎 | 按规则把买卖单对上、生成成交记录、更新订单状态的系统 |
| 开仓 | 首次建多或建空，形成持仓 |
| 加仓 | 同方向再开，持仓量增加，占用和开仓均价重算 |
| 减仓 | 同方向平掉一部分，持仓量减少，释放保证金、实现部分盈亏 |
| 平仓 | 全部平掉，仓位归零 |
| 插针 | 盘口瞬间剧烈波动、价格一根针打上去或打下去，若用最新价算强平会误爆；所以用标记价/指数价（限幅、延时） |
| 标记价 | 用于算盈亏和强平的参考价，一般不用最新成交价，防插针 |
| 指数价 | 来自外部（如多家现货均价），用于资金费或标记价 |
| 保证金率 | 权益 / 占用保证金，低于阈值触发强平 |
| 强平 | 保证金不足时系统强制平仓，避免亏损超过保证金 |
| 穿仓 | 强平后亏损超过保证金，需风险准备金或对手方分摊 |
| 资金费 | 永续合约多空双方按周期互付，使合约价锚定现货 |
| ADL | 自动减仓，极端时按规则减对手方盈利仓位填穿仓 |
| 幂等 | 同一请求多次执行结果一致，如重复充值回调只入账一次 |
| 熔断 | 达到阈值（如涨跌幅、错误率）时暂停或缩小范围（如只许撤单、禁止新单），防止事态扩大 |
| 降级 | 压力或依赖异常时关闭非核心功能、保核心（如关推送保交易），牺牲部分体验换稳定 |
| 质量门禁 | 发布前必须通过的检查项（如 P0/P1 清零、核心用例通过、回归通过、对账无差异），不通过则卡住发布 |
| 准入/准出 | 准入=提测/开始测试的前提（如冒烟通过、环境就绪）；准出=允许上线的条件（满足门禁、无发布红线、签字） |
| 发布红线 | 一旦触发必须拦停发布的问题类型（如资金/订单 P0、对账不平、核心接口失败率超阈），红线不关闭不发布 |
| 质量左移 | 提前发现问题的实践：需求/设计阶段参与评审、接口契约先行、提测前开发自测与冒烟，减少缺陷逃逸 |
| 全链路压测 | 在接近线上的完整链路上做压测（如订单→支付→清算），验证限流/降级/熔断与容量，大促或大版本前执行 |

## 六、和「链上/合约」能对上啥（和本仓库的测试能类比）

| 交易所里 | 链上/合约里 | 测试思路可以咋对应 |
|----------|-------------|----------------------|
| 账户余额、订单冻结、成交 | 合约 state、链上 balance | 就像本项目里「合约 getStats 和链上 get_balance 要对上」 |
| 订单状态变来变去 | 合约状态/事件 | 状态流转 + 异常（重复撤单、超时） |
| 撮合结果、成交回报 | 链上交易、receipt | 接口断言 + 一致性校验 |
| 充值入账（链上确认） | 链上监听 + 入账服务 | 同一笔 tx 别重复入、确认数策略 |
| 提现（先扣余额再发 tx） | 私钥签名发交易 | 扣款和链上 tx 一致，失败要回滚或重试 |
